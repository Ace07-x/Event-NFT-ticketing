# 🎟️ Event Ticketing dApp

A decentralized event ticketing application built on Ethereum. Tickets are minted as **ERC-721 NFTs** with on-chain metadata, enforced anti-scalping rules, and a built-in resale market with organizer royalties — all powered by a Solidity smart contract and a vanilla HTML/CSS/JS frontend.

---

## ✨ Features

- **NFT Tickets** — Each ticket is a unique ERC-721 token with on-chain SVG art and JSON metadata
- **Two Ticket Tiers** — General Admission (0.01 ETH) and VIP (0.05 ETH)
- **Anti-Scalping** — Resale price capped at 120% of the original mint price, enforced by the smart contract
- **Organizer Royalties** — 10% of every resale automatically goes to the organizer
- **Ticket Verification** — Anyone can verify a ticket's authenticity, ownership, and type by Token ID
- **Revenue Withdrawal** — Organizer can withdraw accumulated ETH from primary sales at any time
- **Fully On-Chain** — All ticket metadata and SVG artwork stored directly on-chain (no external server required)
- **O(1) Ownership Lookups** — Custom `_update()` hook for gas-efficient per-wallet ticket queries

## 🚀 Quick Start

### Prerequisites

- [Node.js](https://nodejs.org/) (v18+)
- npm

### 1. Install root dependencies

```bash
npm install
```

### 2. Install frontend dependencies

```bash
cd frontend
npm install
cd ..
```

### 3. Compile the smart contract

```bash
npx hardhat compile
```

### 4. Start the local Hardhat blockchain

In a dedicated terminal, run:

```bash
npx hardhat node
```

This starts a local Ethereum node at `http://127.0.0.1:8545` with 20 test wallets pre-funded with 10,000 ETH each. Leave this running.

### 5. Deploy the contract

In a second terminal:

```bash
npx hardhat ignition deploy ignition/modules/EventTicket.js --network localhost
```

Take note of the deployed contract address printed in the output (e.g., `0xe7f1725...`). If it differs from the address hardcoded in `frontend/main.js`, update `CONTRACT_ADDRESS` accordingly.

### 6. Start the frontend

```bash
cd frontend
npm run dev
```

Open [http://localhost:5173](http://localhost:5173) in your browser.

## 📖 How It Works

| Flow | Description |
|------|-------------|
| **Buy Ticket** | User clicks Buy → `purchaseTicket(type, uri)` called with ETH → NFT minted to buyer's wallet |
| **View Tickets** | `getTicketsByOwner(address)` returns all Token IDs → metadata decoded from on-chain URI |
| **List for Resale** | `listForResale(tokenId, price)` — price enforced ≤ 120% of original |
| **Buy Resale** | `buyResaleTicket(tokenId)` → 90% to seller, 10% royalty to organizer, NFT transferred |
| **Verify Ticket** | `getTicketInfo(tokenId)` → returns owner, type, original price, and URI (gas-free read) |
| **Withdraw Revenue** | `withdraw()` — organizer only, transfers contract balance to owner wallet |

For a full step-by-step walkthrough, see [HOW_IT_WORKS.md](./HOW_IT_WORKS.md).

## ⚠️ Known Limitations

This project is a **local development prototype** and is **not production-ready**. Key limitations include:

- 🔴 **Hardcoded private key** in `frontend/main.js` — insecure, for local dev only
- 🔴 **No MetaMask/wallet support** — uses a hardcoded `ethers.Wallet` instead of a browser wallet provider
- 🔴 **Local-only** — configured for the Hardhat node at `127.0.0.1:8545`, not any public network
- 🟠 **No ticket validation at entry** — no `useTicket()` function to mark tickets as consumed
- 🟠 **No resale delisting** — sellers cannot cancel an active listing
- 🟠 **Single event per contract** — no factory pattern for multi-event deployments

See [LIMITATIONS.md](./LIMITATIONS.md) for a full prioritized list.

## 🔮 Roadmap

Planned improvements across 8 phases:

1. **Production Readiness** — MetaMask integration, public testnet deployment, `.env` config, security audit
2. **Multi-Event Architecture** — `EventFactory` contract, rich on-chain event metadata, date-gating
3. **Security** — Role-based access control, `Pausable` circuit breaker, per-wallet purchase limits
4. **Core Ticketing** — `useTicket()` scan & entry, resale delisting, multiple ticket tiers
5. **Decentralized Storage** — IPFS/Arweave for metadata, dynamic NFT artwork
6. **Resale Marketplace** — On-chain listing enumeration, marketplace UI, royalty splitting
7. **Scalability** — Layer 2 deployment (Polygon/Arbitrum), gasless meta-transactions, batch minting
8. **Analytics & Integrations** — On-chain dashboard, Etherscan verification, OpenSea compatibility, QR scanner app

See [FUTURE_SCOPE.md](./FUTURE_SCOPE.md) for the full roadmap with implementation details.
